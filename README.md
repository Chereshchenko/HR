## 👔 HR Platform – система управления резюме
Веб-приложение для управления резюме кандидатов с разграничением доступа по ролям.
Платформа позволяет кандидатам создавать и редактировать свои резюме, HR-менеджерам – просматривать все резюме, а администраторам – выполнять любые операции (CRUD). Авторизация реализована через токены (DRF Token Authentication).

## 🎯 Функциональные возможности
## 👤 Роли пользователей
Кандидат (CANDIDATE)
- может создавать и редактировать только свои резюме;
- может просматривать только свои резюме (список и детали);
- не видит резюме других кандидатов.

HR-менеджер (HR)
- имеет доступ к просмотру (GET) всех резюме всех кандидатов;
- НЕ может создавать, редактировать или удалять резюме.

Администратор (ADMIN)
- полный доступ: создание, чтение, обновление, удаление любых резюме.

## 🔐 Аутентификация и токены
- Регистрация пользователя через /api/register/ (доступно всем).
- Получение токена через /api/login/ (передаются username и password).
- Выход из системы через /api/logout/ (только для авторизованных).
- Все запросы к API резюме требуют наличия токена в заголовке: Authorization: Token <your_token>

## 🛠️ Стек технологий
- Python 3.10+
- Django – бекенд-фреймворк
- Django REST Framework (DRF) – создание API
- Token Authentication (DRF) – авторизация
- SQLite / PostgreSQL – база данных

## 📂 Модели данных
User (расширенная модель пользователя)
- username, email, password (стандартные поля Django)
- role – выбор из: CANDIDATE, HR, ADMIN
- методы-свойства: is_candidate, is_hr, is_admin

Resume
- user – внешний ключ к User (связь один-ко-многим)
- position – должность (CharField)
- experience – описание опыта (TextField)
- created_at – дата создания (автоматически)

## 🚀 Установка и запуск
1. Клонируйте репозиторий:

git clone https://github.com/ваш-username/hr-platform.git
cd hr-platform

2. Создайте виртуальное окружение и активируйте его:

python -m venv venv
source venv/bin/activate      # Linux/Mac
venv\Scripts\activate         # Windows

3. Установите зависимости:

pip install -r requirements.txt
(В requirements.txt должны быть: Django, djangorestframework, django-filter – по желанию.)

4. Примените миграции:

python manage.py makemigrations
python manage.py migrate

5. Создайте суперпользователя (администратора):

python manage.py createsuperuser
Укажите логин, email и пароль – у этого пользователя роль будет ADMIN.

5. Запустите сервер разработки:

python manage.py runserver
API будет доступно по адресу http://127.0.0.1:8000/api/.

## 🔐 Права доступа (детали)
- Реализовано через кастомные permission классы:
- ResumePermissions – общий класс для всех операций.
- has_permission (на уровне запроса):
- для безопасных методов (GET, HEAD, OPTIONS) – доступ есть у любого авторизованного пользователя;
- для POST – доступ есть у кандидата или администратора;
- остальные методы (PUT, PATCH, DELETE) проверяются на уровне объекта.
- has_object_permission (на уровне объекта):
- администратор – всегда разрешено;
- HR – разрешены только безопасные методы (чтение);
- кандидат – разрешены безопасные методы и, если объект принадлежит ему, то также изменение и удаление (но удаление кандидату не разрешено на уровне has_permission, здесь фактически только изменение).
